\section{Матричный алгоритм для нескольких источников}
\label{sec:MatrixMultiSource}
\tikzsetfigurename{CFPQ_MatrixMultiSource_}

Матричный алгоритм, описанный в разделе~\ref{sec:MatrixCFPQ}, решает задачу КС-достижимости для всех пар вершин (all-pairs).
Во многих практических сценариях такой полный перебор избыточен: как правило, интерес представляют пути, начинающиеся из относительно небольшого множества заданных стартовых вершин.
Например, при анализе графов данных пользователь может указать конкретные вершины как источники запроса, и вычисление достижимости для всех остальных вершин является лишней работой, потребляющей время и память.

В данном разделе мы рассмотрим модификацию матричного алгоритма, позволяющую ограничить вычисления только парами $(s, v)$, где $s$ принадлежит заданному множеству стартовых вершин $\mathit{Src}$~\sidecite{Terekhov2021MultipleSourceCP}.
Идея состоит в том, чтобы отслеживать, для каких нетерминалов грамматики и из каких стартовых вершин уже вычислены или вычисляются пути, и распространять эту информацию только вдоль релевантных рёбер графа.

\subsection{Описание алгоритма}
\label{subsec:MatrixMultiSource_description}
\tikzsetfigurename{CFPQ_MatrixMultiSource_Desc_}

Пусть $\mbfscrG = \langle V, E, L \rangle$~--- входной помеченный граф и $G = \langle \Sigma, N, P, S \rangle$~--- КС-грамматика в ослабленной нормальной форме Хомского (ОНФХ, определение~\ref{def:wCNF}).
В отличие от базового алгоритма, мы дополнительно задаём множество стартовых вершин $\mathit{Src} \subseteq V$ и для каждой вершины $v \in \mathit{Src}$ инициализируем $T^S[v,v] = \mathit{true}$.

Основная идея модификации заключается во введении дополнительных булевых матриц $TSrc^A$ для каждого нетерминала $A \in N$.
Матрица $TSrc^A$ отмечает стартовые вершины, из которых уже вычисляются пути, соответствующие нетерминалу $A$: $TSrc^A[v,v] = \mathit{true}$ означает, что пути, выводимые из $A$ и начинающиеся в вершине $v$, учитываются при дальнейших вычислениях.
Иными словами, $TSrc^A$ задаёт <<фронт>> стартовых вершин для нетерминала $A$.

При обработке бинарного правила $A \to B\ C$ стандартное умножение $T^A = T^A + (T^B * T^C)$ заменяется на
\[
    M \gets TSrc^A * T^B, \qquad
    T^A \gets T^A + M * T^C,
\]
где $M$~--- промежуточная матрица, содержащая пары $(s, v)$ такие, что существует путь из $s$, выводимый из $B$ и заканчивающийся в $v$, а $s$ отмечена в $TSrc^A$.
Таким образом, первый сомножитель фильтрует стартовые вершины: вычисляются только те продолжения, которые начинаются из вершин, релевантных для $A$.

После обновления $T^A$ необходимо перенести информацию о стартовых вершинах на нетерминалы правой части правила:
\begin{itemize}
    \item $TSrc^B \gets TSrc^B + TSrc^A$~--- все стартовые вершины для $A$ становятся стартовыми и для $B$;
    \item $TSrc^C \gets TSrc^C + \textsc{GetDst}(M)$~--- если путь из $s$, выводимый из $B$, заканчивается в $v$, то вершина $v$ становится стартовой для $C$, поскольку дальнейший путь, выводимый из $C$, должен начинаться именно в $v$.
\end{itemize}

Функция $\textsc{GetDst}(M)$ строит диагональную матрицу, содержащую $\mathit{true}$ в позиции $(v,v)$ для каждого столбца $v$, в котором матрица $M$ имеет хотя бы одно истинное значение.
Формально,
\[
    \textsc{GetDst}(M)[i,j] =
    \begin{cases}
        \mathit{true}, & i = j \text{ и } \exists k: M[k,i] = \mathit{true}, \\
        \mathit{false}, & \text{иначе.}
    \end{cases}
\]

Псевдокод алгоритма приведён в листинге~\ref{algo:MatrixMultiSource}.
Основной цикл повторяется до тех пор, пока любая из матриц $T^A$ или $TSrc^A$ изменяется.
После завершения результат для стартового нетерминала $S$ и заданного множества $\mathit{Src}$ получается как $MSrc * T^S$, где $MSrc$~--- диагональная матрица размера $|V| \times |V|$, в которой $MSrc[v,v] = \mathit{true}$ тогда и только тогда, когда $v \in \mathit{Src}$.

\begin{algorithm}
    \KwData{$\mbfscrG = \langle V, E, L \rangle$~--- помеченный граф; $G = \langle \Sigma, N, P, S \rangle$~--- грамматика в ОНФХ; $\mathit{Src} \subseteq V$~--- множество стартовых вершин}
    \KwResult{Булева матрица $R$ размера $|\mathit{Src}| \times |V|$, где $R[s,v] = \mathit{true} \iff$ существует путь из $s$ в $v$, выводимый из $S$}
    \ForEach{$A \in N$}{
        $T^A \gets \mathbb{0}_{|V| \times |V|}$\;
        $TSrc^A \gets \mathbb{0}_{|V| \times |V|}$\;
    }
    \ForEach{$v \in \mathit{Src}$}{
        $TSrc^S[v,v] \gets \mathit{true}$\;
    }
    $MSrc \gets TSrc^S$\;
    \ForEach{$A \to x \in P$}{
        \ForEach{$(v, u) \in E$ с меткой $x$}{
            $T^A[v,u] \gets \mathit{true}$\;
        }
    }
    \While{$T$ или $TSrc$ изменяются}{
        \ForEach{$A \to B\ C \in P$}{
            $M \gets TSrc^A * T^B$\;
            $T^A \gets T^A + M * T^C$\;
            $TSrc^B \gets TSrc^B + TSrc^A$\;
            $TSrc^C \gets TSrc^C + \textsc{GetDst}(M)$\;
        }
    }
    \KwRet{$MSrc * T^S$}\;
    \caption{Матричный алгоритм КС-достижимости для нескольких источников}
    \label{algo:MatrixMultiSource}
\end{algorithm}

Алгоритм естественным образом поддерживает и случай одного источника (single-source), когда $\mathit{Src}$ состоит из единственной вершины.

\paragraph{Версия с кэшированием.}
Если к одному и тому же графу выполняется последовательность запросов с разными множествами стартовых вершин, можно использовать кэширование уже вычисленных результатов.
Версия с кэшированием (листинг~\ref{algo:MatrixMultiSourceCache}) хранит индекс $\mathit{Index} = (T, TSrc)$, который содержит матрицы $T^A$ и $TSrc^A$, накопленные в результате обработки предыдущих запросов.
При выполнении нового запроса для множества $\mathit{Src}$ из него исключаются вершины, для которых $TSrc^S[v,v]$ уже истинно (то есть пути из которых уже вычислены), и алгоритм достраивает только недостающую информацию.
Однако, как показано в экспериментальном исследовании~\sidecite{Terekhov2021MultipleSourceCP}, накладные расходы на поддержку кэша часто перевешивают выигрыш от повторного использования результатов, поэтому наивная версия без кэширования оказывается предпочтительнее на практике.

\begin{algorithm}
    \KwData{$\mbfscrG$~--- граф; $G$~--- грамматика в ОНФХ; $\mathit{Index} = (T, TSrc)$~--- накопленный индекс; $\mathit{Src}$~--- множество стартовых вершин}
    \KwResult{Булева матрица результата}
    \ForEach{$A \in N$}{
        $TNewSrc^A \gets \mathbb{0}_{|V| \times |V|}$\;
    }
    \ForEach{$v \in \mathit{Src}$}{
        \If{$TSrc^S[v,v] = \mathit{false}$}{
            $TNewSrc^S[v,v] \gets \mathit{true}$\;
        }
    }
    $MSrc \gets TNewSrc^S$\;
    \While{$T$ или $TNewSrc$ изменяются}{
        \ForEach{$A \to B\ C \in P$}{
            $M \gets TNewSrc^A * T^B$\;
            $T^A \gets T^A + M * T^C$\;
            $TNewSrc^B \gets TNewSrc^B + (TNewSrc^A \setminus TSrc^B)$\;
            $TNewSrc^C \gets TNewSrc^C + (\textsc{GetDst}(M) \setminus TSrc^C)$\;
        }
    }
    \KwRet{$MSrc * T^S$}\;
    \caption{Матричный алгоритм КС-достижимости для нескольких источников с кэшированием}
    \label{algo:MatrixMultiSourceCache}
\end{algorithm}

    . & . & . & . & . & . \\
    . & . & . & . & . & . \\
    . & . & . & . & . & . \\
    . & . & . & . & . & .
    \end{pmatrix}.
\]
}
Таким образом, из стартовой вершины $2$ достижимы вершины $4$ и $5$ по путям, слова которых выводимы из $S$.
Умножение $MSrc * T^S$ даёт матрицу результата размера $1 \times 6$, в которой истинны столбцы $4$ и $5$.

\subsection{Формальные свойства и доказательства}
\label{subsec:MatrixMultiSource_properties}
\tikzsetfigurename{CFPQ_MatrixMultiSource_Props_}

\begin{theorem}[Корректность]
    Алгоритм~\ref{algo:MatrixMultiSource} вычисляет в точности множество пар $(s, v)$, где $s \in \mathit{Src}$ и существует путь из $s$ в $v$, слово которого выводимо из стартового нетерминала $S$ в грамматике $G$.
\end{theorem}

\begin{proof}
    Доказательство основано на доказательстве корректности базового матричного алгоритма~\sidecite{Azimov:2018:CPQ:3210259.3210264}.
    Покажем, что на каждом шаге матрицы $TSrc^A$ содержат в точности те стартовые вершины, из которых уже вычисляются или будут вычислены пути, выводимые из нетерминала $A$.

    База: перед первой итерацией $TSrc^S$ инициализирована множеством $\mathit{Src}$, а все остальные $TSrc^A$ пусты.
    Это соответствует тому, что изначально пути, выводимые из $S$, интересуют нас только для вершин из $\mathit{Src}$.

    Индукционный переход. Рассмотрим обработку правила $A \to B\ C$ на произвольной итерации.
    Пусть перед обработкой $TSrc^A$ содержит стартовые вершины, для которых пути из $A$ уже вычисляются.
    Произведение $M = TSrc^A * T^B$ даёт все пары $(s, v)$ такие, что $s$~--- стартовая вершина для $A$, и существует путь из $s$, выводимый из $B$ и заканчивающийся в $v$.
    Тогда $T^A = T^A + M * T^C$ добавляет пути, продолжающие найденные пути из $B$ продолжением, выводимым из $C$.
    Обновление $TSrc^B = TSrc^B + TSrc^A$ гарантирует, что все стартовые вершины для $A$ становятся стартовыми и для $B$: если нас интересует путь из $s$, выводимый из $A = BC$, то нас интересует и его префикс из $s$, выводимый из $B$.
    Наконец, $\textsc{GetDst}(M)$ добавляет в $TSrc^C$ вершины-концы путей из $B$: продолжение, выводимое из $C$, должно начинаться именно там, где закончился путь из $B$.

    Таким образом, на каждой итерации $TSrc$-матрицы точно отражают множество стартовых вершин, для которых вычисляются пути.
    Поскольку основной цикл завершается только когда ни одна матрица не изменяется, по завершении $T^S$ содержит все пары $(s,v)$ для $s \in \mathit{Src}$, что и требовалось.
\end{proof}

Временная сложность алгоритма не превосходит сложности базового матричного алгоритма, умноженной на число стартовых вершин в худшем случае.
Действительно, каждая итерация основного цикла выполняет $|P_{\mathit{bin}}|$ умножений булевых матриц размера $|V| \times |V|$, а число итераций ограничено $|V| \cdot |N|$ (поскольку на каждой итерации хотя бы одна матрица $T^A$ или $TSrc^A$ изменяется, а общее число возможных изменений конечно).

Основное преимущество алгоритма~--- не асимптотическая сложность, а практическая эффективность: когда $|\mathit{Src}| \ll |V|$, матрицы $TSrc^A$ и промежуточные матрицы $M$ сильно разрежены, что позволяет существенно сократить объём вычислений и потребление памяти по сравнению с полным матричным алгоритмом для всех пар.
