# Материалы по достижимости с ограничениями в виде формальных языков
- В данном проекте находятся исходники книги на TeX.
- Книга на русском. Язык изложения --- русский.
- Корневой файл: `tex/FormalLanguageConstrainedReachabilityLectureNotes.tex`
- Для базовой быстрой навигации по книге можно использовать `book_structure.md`. В нём структура книги по файлам и краткое содержимое. Не забывай обновлять структуру и краткое содержание, если что-то изменил, добавил, удалил.

## Сборка
- Находясь в директории `tex` запустить `latexmk -interaction=nonstopmode -shell-escape FormalLanguageConstrainedReachabilityLectureNotes.tex`
- Не собирай проект без особой необходимости. Это занимает много времени.

## Вёрстка
- Используем `sidenote` вместо `footnote`
- Используем `sidecite` вместо `cite` почти всегда. `cite` используется во вводных частях глав, чтобы не конфликтовало с `margintoc`, и внутри `sidenote`.
- Используем неразрывные пробелы
  - перед тире: `текст~--- текст`
  - перед ссылками: `текст~\cite{...}`, `текст~\sidecite{...}`
- Используем кавычки <<ёлочки>> (`<<ещё раз пример текста в кавычках>>`).
- Для <<выделенных>> (располагаемых на отдельной строке) формул используем `\[ \]`: `\[ math formula \]`.
- У метки`\label` всегда есть префикс, отражающий её тип. Например: `\label{fig:<fig_name>}`, `\label{sec:<section_name>}`
- `\rng` для обозначения диапазонов. Например `$[0 \rng n-1]$` (не `$[0 \ldots n-1]$` или что-нибудь ещё).
- `$\Bbbone$` для нейтрального по умножению
- `$\Bbbzero$` для нейтрального по сложению
- Для строк, цепочек используем w или аналоги, но не $\omega$.
- Используй команды из `styles/math.tex` согласно их описанию в комментариях.

## Правила структурирования и именования файлов


Все исходники лежат в директории `tex/`.

### Терминология:
- часть --- \addpart{PartName}
- глава --- \chapter
- раздел --- \section
- подраздел --- \subsection
- Структурная единица --- часть, глава, раздел, подраздел.
- Вводная часть главы --- то, что идёт до начала первого раздела.
- Вводная часть раздела --- то, что идёт до начала первого подраздела.

### Общие правила
1. Все имена файлов и директорий — только латиница.
2. **Часть** — директория `part_NN_Name/`. Содержит `main.tex` (`\addpart` + вводная часть части + `\input` глав) и поддиректории глав.
3. **Глава** — директория `chapter_NN_Name/` внутри своей части. Содержит `main.tex` (`\chapter` + вводная часть главы + `\input` разделов) и файлы разделов. Если глава не разбита на разделы, `main.tex` содержит всё.
4. **Раздел** — файл `NN_Name.tex` рядом с `main.tex` главы. Содержит `\section{...}` и всё наполнение, включая вложенные подразделы (`\subsection`).
5. **Подразделы в отдельные файлы не выносятся и отдельных директорий не имеют.**
6. Каждая структурная единица имеет метку `\label`. Название метки содержательно отражает смысл структурной единицы.
7. В каждом файле, соответствующем структурной единице указывается `\tikzsetfigurename` для этой структурной единицы (соответственно, после <<начала>> этой единицы).
   1. Пример:
  ```
    \chapter{Некоторые понятия линейной алгебры}
    \label{chpt:LinearAlgebraIntro}
    \tikzsetfigurename{LinearAlgebraIntro_}
  ```
8. **Изображения** — в директории `figures/` внутри директории главы. Если рисунков много, группируются в поддиректории, названные по номеру раздела: `figures/03_TensorProduct/`, `figures/05_BottomUp/LR0/` и т.п.
   1. Если изображения используются более чем в одной главе, то выносим в директорию `figures/` на уровне части.
   2. Если изображения используются более чем в одной части, то выносим в директорию `figures/` на верхнем уровне.
   3. Не забыть подкорректировать пути в местах использования изображений.
   4. Все `tikz` изображения выделяются в отдельный `tex` в соответствующую директорию `figures/`
9.  `figures/externalized/` --- техническая директория для `tikz externalized`.
10. `styles/` — настройки отдельных пакетов и вспомогательные функции.

### Frontmatter
- Файлы: `Introduction.tex` и `List_of_contributors.tex` — в директории `frontmatter/`.

## Правила структурирования изложения
1. Не разделяем текст на подразделы если иное не указано явно. Вместо подразделов структурируем текст в виде связанных абзацев с гладкими переходами.
2. Максимально переиспользуем примеры. Если есть возможность использовать уже введённые ранее объекты (граф, грамматику, регулярное выражение и т.д.) для примера, то используем, а не придумываем новые. В идеале --- сквозные примеры для всей книги.
3. Примеры должны быть связаны. отчасти перекликается с предыдущим пунктом. Например, если в одном примере было преобразование объекта А в Б, то при построении примера обратного преобразования покажи преобразование Б в А.
4. Определения выносятся в соответствующие разделы первых двух частей.
5. Текст должен быть строгим. Потому для определений, теорем и т.д. используем соответствующие окружения: `definition`, `theorem` и т.д.
6. Примеры оформляются через окружение `example`.
   1. Очень большие сложные примеры  могут выделяться в отдельный подраздел.

## Работа с литературой
1. Если понадобился текст статьи для анализа, сперва проверь её наличие в директории [papers_pdf/](papers_pdf/)
   1. Название файла --- название статьи.
   2. Для извлечения текста используй либо возможности самой нейронки, либо `pdftotext`
2. Если статьи там нет, то только тогда попробуй скачать её.
   1. Если получилось скачать, добавь её в директорию `papers_pdf` (Название файла --- название статьи).
   2. Если не получилось --- обязательно сообщи.
3. Если нужно создать новую библиографическую запись, сообщи. Не сочиняй записи самостоятельно.

## Работа с tikz
1. Для помощи в определении раскладки есть скрипт `tools/dot2tikz.py`: помогает понять примерное взаимное расположение узлов и сгенерировать черновой tikz по dot.
2. Для некоторых примеров SPPF, GSS, RSM можно использовать `UCFS/UCFS/cfpq-paths-app`. Детали читай в readme в этой папке. Можешь модифицировать код в `/UCFS/UCFS/cfpq-paths-app/src/main/kotlin/org/ucfs/paths/Main.kt`, чтобы подать на вход нужные dot-файлы и RSM. `UCFS.md` содержит описание примера построения примеров SPPF.

## Общие правила работы
1. Если встретил какую-то ошибку (некорректная формулировка, некорректная ссылка, <<битая>> ссылка, странная вёрстка, опечатка, несоблюдение изложенных здесь правил, иное), сразу сообщай.
2. Если встретил какой-то термин или сокращение, которого ещё нет в [glossary.md](glossary.md), сразу сообщай.
3. Если не смог получить доступ к статье (или иному материалу), а он нужен для работы (например, для проверки корректности ссылок или утверждений), сразу сообщай.
4. При необходимости интегрировать исходники статьи в текст книги, пользуйся инструкциями из [paper_integration_roles.md](paper_integration_rules.md).
5. Для разметки текста задачами используем команды, объявленные в `styles/todonotes.tex`. Например, `\fixit`, `\mytodo` или `\mycomment`
   1. Не использовать эти команды внутри окружений типа definition, theorem, example, figure. Ломается компилятор. Лучше вставлять в ближайшее место снаружи от окружения.
