# Материалы по достижимости с ограничениями в виде формальных языков

Этот файл — короткая точка входа для быстрого старта без ошибок. Сам проект описан в `README.md` (вход для навигации по репозиторию).

## Start here

1. Сначала загрузи скилл `workflow-management` (`.opencode/skills/workflow-management/SKILL.md`) — перед любым делом.
2. Прочитай `README.md` для навигации по проекту.
3. Перед навигацией по книге загрузи скилл `project-navigation` (`.opencode/skills/project-navigation/SKILL.md`): навигация через `docs/book-structure.md`, а не обход всего репозитория.

## Main Principles

- Этот файл — короткая точка входа для быстрого старта без ошибок.
- Единый source of truth. Без дублей. Каждая вещь (в исходниках, issues, PR, документации) описана ровно один раз. Используй обобщение, перекрёстные ссылки и подобные техники, чтобы избежать дублей и переиспользовать. Прежде чем создавать новое — найди, что можно переиспользовать.
- Иерархия source of truth: TeX-исходники и их устоявшие конвенции (`tex/styles/`, готовые главы), скрипты, CI > docs. Если факт можно извлечь из исходников/скриптов/CI — он не дублируется в docs. Docs держат только то, что нельзя однозначно восстановить из исходников: проектные решения, нетривиальные ограничения. Скиллы остаются тонкими указателями на docs, исходники, инструменты или CI — они никогда не пересказывают их.
- Инструменты, а не инструкции. Если что-то можно сделать существующим инструментом — сделай. Без долгих инструкций и ручного анализа. Нужен анализ? Запусти инструмент и разбери отчёт.
- Никогда не молчи о проблемах. Любая обнаруженная проблема должна быть обработана. Если она в текущем скоупе или чинится легко (опечатка) — почини, даже если предсуществующая. Если значительно вне скоупа — сообщи пользователю и предложи создать issue.
- Issues, PR и их комментарии — база знаний технических деталей. Записывай находки и идеи по задаче в описании/комментариях соответствующего issue/PR. Столкнувшись с проблемой, сначала посмотри, не решалась ли похожая ранее — ищи решение в существующих issues/PR.
- Всегда учишься, никогда не забываешь — кодируй паттерны до конца сессии (обновляй скиллы / docs / `docs/glossary.md` / `docs/book-structure.md`).
